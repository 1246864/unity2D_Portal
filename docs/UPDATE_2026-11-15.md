## 1. 概览

这次更新把传送门从“水平门 + 传送”推进到支持**任意角度摆放**的完整机制：

1. 传送门开口方向 `OpeningDirection` 实时由 Transform 计算，门旋转后地形开洞、传送判定和特效方向都会同步；
2. 玩家被拆成“物理根节点 + 显示子节点”；
3. 玩家出传送门后只旋转显示节点，胶囊碰撞体保持竖直；
4. 出口位置按出口门法线和切线计算，不再依赖世界 Y；
5. 速度/受力向量按门的法线/切线坐标系变换；
6. 传送门激活时对地形做非整格布尔切割，停用/移动时恢复或跟随；
7. 相机独立于玩家，跟随状态保存在玩家显示节点的局部空间，传送时画面相对玩家连续；
8. 玩家 Inspector 改成中文标签和中文说明。

## 3. 核心机制

### 3.1 玩家显示与物理分离

`PlayerController2D` 的物理根节点保留：

- `Rigidbody2D`
- `CapsuleCollider2D`
- `Center Point`（传送门薄碰撞箱检测点）

显示部分在运行时拆到子节点 `Player Visual`：

- 根节点上的 `SpriteRenderer` 会复制到 `Player Visual`，然后禁用根节点渲染；
- 排序层、排序顺序、颜色、材质、翻转等属性一并复制；
- 传送门旋转只修改 `Player Visual.localRotation`；
- 根节点的 `Transform.rotation` 和 `Rigidbody2D.rotation` 不再改变；
- `CurrentRotationAngle` 读取的是显示节点角度。

这样玩家倾斜/回正时，胶囊碰撞体和物理位置保持不变。

### 3.2 门的实时方向

`CaptureDisplayGroup.OpeningDirection` 是实时属性：

```text
local = Rz(FacingSign * -90°) * Vector2.up
world = transform.TransformDirection(local)
OpeningDirection = normalize(world)
```

- 朝右：`(1, 0)`；
- 朝左：`(-1, 0)`；
- 门整体旋转时结果实时变化；
- `BackDirection = -OpeningDirection`。

地形开洞、门背面判断、提示光带和速度变换都使用这个方向，不再使用固定的 `FacingSign` 水平方向。

### 3.3 出口位置

`PortalPair.Teleport` 计算出口：

```text
front = gateThickness / 2 + centerPointRadius + exitMargin

sourceTangent = source.transform.up
partnerTangent = partner.transform.up
tangentOffset = dot(playerPos - sourcePos, sourceTangent)

target = partnerPos
       + partner.OpeningDirection * front
       + partnerTangent * tangentOffset
```

- 世界 Y 不再参与出口定位；
- 入口时沿门平面的相对高度迁移到出口门的切线方向；
- 出口中心点严格保持在对方门碰撞箱外 `front` 距离；
- 门旋转任意角度都不会因为世界 Y 掺进法线而生成过近的出口。

### 3.4 出口旋转

```text
sourceAngle  = SignedAngle(Vector2.up, source.transform.up)
partnerAngle = SignedAngle(Vector2.up, partner.transform.up)
exitAngle    = DeltaAngle(0, partnerAngle - sourceAngle)
```

即：

```text
出口旋转 = 出口门角度 - 入口门角度
```

玩家进门时是竖直的，所以不需要再叠加玩家角度。`PlayerController2D.TeleportWithPortalRotation`
把显示节点旋转到 `exitAngle`，再按玩家配置回正。

### 3.5 速度/受力向量

`TransformPortalVelocity` 把速度分解到入口门坐标系：

```text
normalSpeed  = dot(velocity, source.OpeningDirection)
tangentSpeed = dot(velocity, source.transform.up)

outVelocity = partner.OpeningDirection * (-normalSpeed)
            + partner.transform.up * tangentSpeed
```

- 法线分量反向（从出口正面出来）；
- 切线分量保留；
- 两门同向时等价于原来的水平反向；
- 两门相对旋转时速度会跟着转到出口门坐标系；
- 速度来源是物理步开始前的 `VelocityBeforePhysics`，避免碰撞回调里被物理解算器改掉。

### 3.6 回正动画

回正参数全部在 `PlayerController2D` 面板：

| 中文标签 | 字段 | 默认 |
|---|---|---:|
| 基础回正速度 | `portalRealignSpeed` | 80 |
| 回正曲线 | `portalRealignCurve` | EaseInOut |
| 下坠加速阈值 | `portalRealignFallSpeedForMaxBoost` | 12 |
| 最大下坠加速倍率 | `portalRealignMaxFallSpeedMultiplier` | 3 |
| 触地回正倍率 | `portalRealignGroundedSpeedMultiplier` | 6 |

计算：

```text
基础时长 = abs(起始角度) / 基础回正速度

下坠速度 = max(0, -Rigidbody2D.velocity.y)
下坠比例 = clamp01(下坠速度 / 下坠加速阈值)
下坠倍率 = lerp(1, 最大下坠加速倍率, 下坠比例)

触地时：最终倍率 = max(下坠倍率, 触地回正倍率)
否则：  最终倍率 = 下坠倍率

回正进度 += Time.deltaTime * 最终倍率
```

- 回正在 `Update` 中推进，与渲染帧率一致；
- 曲线控制回正过程中的角度分布；
- 下坠越快、触地时回正越快；
- 只旋转 `Player Visual`，碰撞体不变。

### 3.7 相机

`CameraFollow2D` 保持相机为独立场景对象，但把跟随状态放在玩家显示节点的局部空间：

```csharp
_localOffset = _visual.InverseTransformPoint(transform.position);
```

每帧：

```csharp
transform.position = _visual.TransformPoint(_localOffset);
transform.rotation = _visual.rotation;
```

传送时不需要额外把相机搬到某个世界坐标：

- 玩家显示节点从 `T0` 变为 `T1`；
- 相机保持同一个 `_localOffset`；
- 世界变换自然满足 `C1 = T1 * T0^-1 * C0`；
- 画面相对玩家的位置和旋转保持连续；
- 多次传送不会累计 offset 误差。

前瞻也投影到玩家显示节点的局部 X 轴；回正期间禁用前瞻，避免相机被拉开。

### 3.8 地形动态开洞

`PortalTerrainCarver` 由 `PortalPair` 在运行时按需补上，核心逻辑：

- 以门中心为起点，沿 `BackDirection` 取长度 `carveWidth`；
- 高度取门洞 `PortalHeight`，居中；
- 向门面方向额外扩展 `carveFrontMargin`；
- 收集所有激活门的矩形；
- 对每个被覆盖的 Tilemap 格子，用格子 Sprite 的物理形状和矩形做布尔差；
- 完全删除的格子把 `Tile.colliderType` 设为 `None`；
- 部分删除的格子创建运行时 `Sprite` + `Tile`，保留原图但替换物理形状；
- 不调用 `Tilemap.RefreshAllTiles()`，避免重置 per-cell collider override；
- 重新生成 `TilemapCollider2D` 和 `CompositeCollider2D`；
- 门停用、场景卸载或矩形变化时恢复原 Tile，再按当前矩形重建。

开洞不是整格删除，因此可以切出半格甚至更小的碰撞碎片，同时保持视觉瓦片不变。

### 3.9 中文检查器

`Assets/Editor/PlayerController2DEditor.cs` 为 `PlayerController2D` 提供自定义 Inspector：

- 所有字段显示中文标签；
- 鼠标悬停显示中文说明；
- 分组为水平移动、跳跃、地面检测、重生、传送门碰撞点、显示、传送门旋转、回正动态加速。

C# 内部字段名保持不变，避免破坏 Prefab/场景序列化和测试引用。
