## 1. 概览

本次把传送门从视觉原型推进到可玩的传送：

1. 门内有一道**极薄碰撞箱**（厚度 0.05，高度等于门洞高度）；
2. 玩家中心新增一个**碰撞点**，刚体使用**连续碰撞**，只有这个点会撞到薄箱，身体胶囊不会提前挡住门；
3. 撞到即传送：玩家被强制放到另一扇门 `facing` 一侧、碰撞箱外一点点（约 0.135 格）；
4. 传送当帧**强制两扇门的捕获相机各拍一次**，并重新做半屏成像；
5. 玩家绕到门背面（与开口方向夹角 ≥ 90°）时，**隐藏该门画面**。

同时，场景里的 A/B 两门被移动到地面附近并互换朝向，现在**面对面**，玩家从中间直接走进去即可。

## 3. 脚本改动

### 3.1 `PlayerController2D.cs`

- 新增参数 `centerPointRadius = 0.08`（带中文 Tooltip）；
- `Awake` 时在玩家中心创建子物体 `Center Point`，挂 **CircleCollider2D**（非 Trigger）；
- `Rigidbody2D.collisionDetectionMode = Continuous`，高速穿过薄箱时不穿模；
- `FixedUpdate` 末尾缓存 `VelocityBeforePhysics`：碰撞回调里 `rb.velocity` 可能已被物理解算器改掉，传送时用它恢复进门瞬间的速度；
- 公开 `CenterPoint` 供传送门判定；`OnDrawGizmosSelected` 画出中心碰撞点。

### 3.2 `CaptureDisplayGroup.cs`

**传送参数**

| 字段 | 默认 | 说明 |
|---|---|---|
| `teleportCooldown` | 0.25 | 冷却秒数，两门共享 |
| `preserveVelocity` | true | 传送后是否保留速度 |
| `gateThickness` | 0.05 | 薄碰撞箱厚度（世界单位） |
| `exitMargin` | 0.03 | 出口离碰撞箱外表面的额外距离 |

**薄碰撞箱**

- `Awake` / `Start` 在门根节点上确保一个 `BoxCollider2D`：`size = (gateThickness, PortalHeight)`、非 Trigger；
- `LateUpdate` 里 `UpdateGateSize()`：遮罩偏移改了，箱子高度自动跟随；
- `OnDrawGizmosSelected` 用橙色线框把不可见的箱子画出来。

**只让中心点碰撞**

- `ConfigurePlayerCollision()` 调用 `Physics2D.IgnoreCollision(玩家胶囊, 碰撞箱, true)`，身体胶囊和门箱互不碰撞；
- `OnCollisionEnter2D` / `OnCollisionStay2D` 里校验 `collision.collider == PlayerController2D.CenterPoint` 才触发。

**传送位移**

```text
front   = gateThickness/2 + centerPointRadius + exitMargin   ≈ 0.135
targetX = partner.x + partner.FacingSign * front
targetY = partner.y + (player.y - portal.y)                  // 保留相对高度
```

- 出口固定落在对方门 `facing` 一侧、碰撞箱外一点点（不再是 16px 的前推）；
- 速度：两门朝向相同则水平速度取反，相背则保持；
- 相机：传送前记录主相机与玩家的相对位置，传送后瞬间搬到"新玩家 + 同一相对位置"；
- 两扇门同时进入冷却，避免刚落地就被另一扇门弹回去。

**传送后强制刷新**

- 传送收尾置 `_forceCapture = true`；
- 同帧 `LateUpdate` 执行 `ForceCaptureBoth()`：两台捕获相机各 `CaptureNow()` 一次，然后两边 `ApplyHalfCrop()` 重新半屏成像；
- 放在 `LateUpdate`（物理回调之后、出帧之前），避免在物理步里 `Camera.Render()`。

**背面隐藏**

- 开口方向 = `Quaternion.Euler(0, 0, FacingSign * -90f) * Vector3.up`（朝右 → `(1,0)`，朝左 → `(-1,0)`）；
- 玩家相对门的向量与开口方向点积 ≤ 0（夹角 ≥ 90°）时，`output.enabled = false`；
- 只关闭 SpriteRenderer，捕获、裁剪、遮罩、颜色逻辑不受影响。

**清理**

- 删除旧的"中轴重合 + 跨轴"判定与 `axisTolerance`；
- 删除 `exitForwardPixels` / `teleportPixelsPerUnit`（改为 `exitMargin` 世界单位）。

### 3.3 门画面颜色（上次逻辑的随本次微调）

- `color_offs` 初值 0.5、距离阈值 5 格；
- 按 `side` 区分 A/B 色调（B 偏红、A 偏蓝）。

## 5. 兼容与注意事项

1. 被删除的 `axisTolerance` / `exitForwardPixels` / `teleportPixelsPerUnit` 在场景里仍是孤立序列化键，Unity 下次保存会自动清理；新增的 `gateThickness` / `exitMargin` 暂时使用默认值。
2. 门背面的**碰撞箱仍然有效**，只是画面隐藏；如果希望"从背面撞门不传送"，需要再按开口方向禁用碰撞箱。
3. 遮罩节点 `View Mask Top/Bottom` 的 scale 仍是旧 `facing` 的翻转（A `(1,-1)`、B `(1,1)`），facing 互换后若门洞视觉方向不对，需要同步调整；后续可按 `facing` 自动设置。
4. 捕获仍以 0.05 秒周期运行，传送后额外强制一次；无头模式（`-nographics`）下 `RegionSnapshotCamera` 自动禁用。
5. `exitMargin` 建议大于物理接触偏移（0.01），否则传送完可能立刻再次接触碰撞箱。
