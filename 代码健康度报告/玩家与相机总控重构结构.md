## 重构目标

原结构中，`PlayerController2D` 自己读取键盘，`PlayerCameraMirror` 修改相机投影和输入方向，`PortalPair` 又直接调用 `CameraFollow2D` 并操作裸相机 Transform，输入和相机控制入口分散。

本次重构建立 `PlayerControlManager` 作为玩家输入与主相机控制的统一门面，同时保留 `PortalPair` 对完整传送流程的编排权。

## 模块结构

```text
键盘 / 鼠标
    │
    ▼
PlayerControlManager（设备输入与主相机总控）
    │
    │ SubmitDeviceInput / JumpPressed / JumpReleased
    ▼
PlayerController2D（移动、跳跃、刚体与物理传送）

CaptureDisplayGroup（碰撞转发、画面显示）
    │
    ▼
PortalPair（传送流程编排者）
    ├──────────────► PlayerController2D.TeleportWithPortalRotation
    │                  玩家出口、角度、速度和物理状态
    │
    └──────────────► PlayerControlManager
                       ├─ TeleportRelative
                       ├─ ToggleMirrorAndInput
                       └─ MirrorPendingCameraPosition
                                  │
                                  ▼
                       CameraFollow2D（跟随与待变换应用）
                                  │
                                  ▼
                               Camera

PlayerControlManager ───────────► Camera.projectionMatrix
PlayerControlManager ───────────► 鼠标屏幕坐标 / 世界坐标转换
```

依赖保持单向：总控不知道 `PortalPair`，`CameraFollow2D` 不知道传送门业务，`PlayerController2D` 不主动寻找相机或传送门。

## 职责边界

| 组件 | 负责 | 明确不负责 |
|---|---|---|
| `PlayerControlManager` | WASD 中的 A/D、空格、鼠标采集；程序输入入口；独立/联动反转；相机传送 API；鼠标世界坐标 | 不决定传送时机和出口，不实现平台物理，不实现相机跟随算法 |
| `PortalPair` | 碰撞后的传送决策、出口计算、玩家物理传送、速度变换、冷却、开门动画、捕获刷新、同向镜像决策 | 不读取硬件输入，不直接修改投影矩阵，不直接操作相机 Transform |
| `PlayerController2D` | 水平速度、跳跃缓冲、土狼时间、重力、精灵朝向、物理传送与回正 | 不读取 Unity Input，不管理相机，不寻找传送门 |
| `CameraFollow2D` | 日常追踪、前瞻、平滑、回正跟随、待传送和待镜像变换应用 | 不读取输入，不决定传送规则 |
| `CaptureDisplayGroup` | 捕获显示、遮罩、半屏、碰撞转发 | 不接管玩家或相机控制 |

## 输入结构

### 设备输入

`PlayerControlManager.Update` 每帧采集：

- A/D：水平值为 D - A，同时按下为 0。
- 空格：按下调用跳跃缓存，松开调用可变跳高截断。
- 鼠标：位置、位移、滚轮、左右中键 held/down/up。

硬件输入只在 `Update` 采样，不在 `FixedUpdate` 中重复采样。`PlayerController2D.FixedUpdate` 继续消费最新移动值和跳跃缓冲。

### 程序输入优先级

`PlayerController2D` 保留两种输入来源，但只有一个硬件输入读取点：

1. 总控通过内部 `SubmitDeviceInput` 提交本帧设备输入。
2. 测试、AI 或其他脚本通过 `SetMoveInput` 进入程序接管状态。

程序接管期间，设备输入不会覆盖外部命令；传入 0 也表示“保持接管并停下”。`ClearManualInput` 清除接管并立即归零，下一帧恢复设备控制。

水平输入统一经过同一个应用函数，确保输入反转只执行一次。

### 生命周期清理

总控禁用时：

- 清除未程序接管的设备移动。
- 清除设备跳跃缓冲并执行跳跃松开处理。
- 恢复玩家输入基线。
- 重置相机投影矩阵。

## 独立与联动 API

| API | 输入方向 | 相机投影 | 用途 |
|---|---|---|---|
| `SetInputInverted(bool)` | 修改 | 不变 | 独立输入反转 |
| `SetCameraMirrored(bool)` | 不变 | 修改 | 独立相机镜像 |
| `SetMirrorAndInput(bool)` | 同步修改 | 同步修改 | 明确设置联动状态 |
| `ToggleMirrorAndInput()` | 切换 | 切换 | 同向传送后处理 |
| `SetMoveInput(float)` | 程序移动 | 不变 | 测试、AI、外部控制 |
| `ClearManualInput()` | 清除程序接管 | 不变 | 恢复设备输入 |

## 鼠标与镜像世界交互

总控提供：

- `MousePosition`、`MouseDelta`、`MouseScrollDelta`。
- `MouseButtonHeld/Pressed/Released(int)`。
- `ScreenToWorldPoint(Vector3)`。
- `MouseWorldPosition`。

后续点击、拖拽和 `Physics2D.OverlapPoint` 等鼠标世界交互，应统一使用总控的坐标转换，不再各自调用 `Camera.main.ScreenToWorldPoint`。

世界坐标在调用时按当前相机投影计算，不缓存镜像前的转换结果。PlayMode 往返测试证明 Unity 2022.3 的 `Camera.ScreenToWorldPoint` 能正确使用当前自定义镜像投影，因此总控不额外翻转屏幕 X，避免双重补偿。

## 传送调用顺序

`PortalPair` 仍拥有完整传送流程：

1. 校验中心碰撞点和冷却。
2. 停止并重播开门动画。
3. 计算出口、玩家角度、速度和相机相对矩阵。
4. 调用 `PlayerController2D.TeleportWithPortalRotation` 完成玩家物理传送。
5. 恢复经出口坐标系变换后的速度。
6. 调用总控 `TeleportRelative` 登记相机相对传送。
7. 设置共享冷却并登记双门捕获刷新。
8. 同向传送时，先调用 `ToggleMirrorAndInput`，再调用 `MirrorPendingCameraPosition`。
9. `CameraFollow2D.LateUpdate` 按自己的规则应用待传送和待镜像变换。

相机内部实现由总控封装，但是否传送、何时镜像以及执行顺序仍由 `PortalPair` 决定。
