# 传送门透明仲裁

## 1. 目标

本次重构将双门透明度从两门各自计算改为由 `PortalPair` 统一仲裁，满足以下规则：

- 每个 `PortalPair` 内同一时间最多一扇门应用透明。
- 自动模式下，玩家正在接近的门保持不透明，另一扇门根据接近程度透明。
- 支持手动选中一扇门，被选门保持不透明，其搭档透明。
- 接近程度不只看直线距离，还考虑门的开口朝向、正背面和沿门面的切向偏移。
- 双门同时进入衰减范围时自动缩小实际阈值，避免透明目标交换时跳变。
- 传送完成后当帧重新计算并应用，出口门立即恢复不透明。

仲裁范围仅限每一对门，不做跨 `PortalPair` 的全局仲裁；本期只提供选中 API，不绑定鼠标或按键。

## 2. 职责边界

| 模块 | 职责 |
| --- | --- |
| `PortalPair` | 计算 A/B 接近评分，确定唯一 source/target，计算目标 alpha，并在传送及选中事件后立即重算 |
| `CaptureDisplayGroup` | 提供视觉中心、开口方向和衰减距离配置；接收 Pair 下发的 alpha；合成最终颜色 |
| `PlayerController2D` | 继续负责玩家移动和物理位置，不参与透明仲裁 |
| `CameraFollow2D` / `PlayerControlManager` | 继续负责相机追踪、镜像和输入，不参与透明评分 |

核心概念：

- `source`：当前接近基准门，alpha 固定为 1。
- `target`：source 的搭档，接收计算出的 alpha。
- 自动模式的 source 每帧由评分决定；选中模式的 source 固定为被选门。

## 3. 朝向感知接近评分

评分以玩家眼睛 `PlayerEye` 和门的视觉中心 `ViewAnchor` 为基准：

```text
delta = PlayerEye - portal.ViewAnchor.position
normal = Dot(delta, portal.OpeningDirection)
tangent = Dot(delta, portal.transform.up)
```

`normal > 0` 表示玩家位于开口正面，`normal < 0` 表示位于背面。背面不直接排除，而是增加固定惩罚：

```text
normalCost = normal >= 0
    ? normal
    : backPenalty + Abs(normal)

score = normalCost * Max(0, normalWeight)
      + Abs(tangent) * Max(0, tangentWeight)
```

评分越低，越适合作为 source：

- 正面越靠近门，评分越低。
- 沿门面方向偏离中心越远，评分越高。
- 位于背面时同时承担固定惩罚和背向距离。
- `OpeningDirection` 每次实时读取，因此门旋转或运行时切换 `Facing` 后会自动使用新朝向。

默认配置：

- `approachNormalWeight = 1`
- `approachTangentWeight = 1`
- `approachBackPenalty = 10`
- `otherViewFadeDistance = 3`

`otherViewFadeDistance` 是评分衰减上限，与评分使用同一成本单位，不再表示纯欧氏距离。

## 4. 自动仲裁

普通移动时在 `PortalPair.LateUpdate` 中同时计算 A/B 评分：

1. 评分较低的门成为 source，另一扇成为 target。
2. source 的 alpha 立即写为 1。
3. target 的 alpha 由 source 评分、target 评分和 source 的 `otherViewFadeDistance` 共同决定。
4. 仅当两门评分近似相等时保留上一帧自动 source，避免等分线上无意义翻转。

双门 alpha 在同一个评估调用中写入，不存在两门分别更新造成的竞争，也不存在两扇同时半透明的交接阶段。

## 5. 自适应衰减阈值

固定阈值在双门同时进入衰减范围时会产生交换跳变：如果 source 在等分点从 A 换成 B，画面可能从 `(A=1, B<1)` 突然变成 `(A<1, B=1)`。

因此实际阈值取配置上限和搭档评分中的较小值：

```text
sourceScore = source 的接近评分
partnerScore = target 的接近评分
maxFade = source.otherViewFadeDistance

effectiveFade = Min(maxFade, Max(0, partnerScore))
targetAlpha = effectiveFade > 0.0001
    ? Clamp01(sourceScore / effectiveFade)
    : 1
sourceAlpha = 1
```

当 `maxFade <= 0` 时同样直接保持不透明，避免除零。

### 双门都在范围内

当 `partnerScore < maxFade` 时，实际阈值缩小为 `partnerScore`。玩家接近自动交换点时：

```text
sourceScore → partnerScore
sourceScore / effectiveFade → 1
```

因此交换前 target 已恢复到 1；交换瞬间两门均为 1，随后新 target 才根据新 source 的评分进入下一段衰减曲线。

### 搭档在范围外

当 `partnerScore >= maxFade` 时，`effectiveFade = maxFade`，退化为固定阈值曲线，远处搭档不会长期保持透明。

### 非对称配置

A/B 可以使用不同的 `otherViewFadeDistance`。每次只读取当前 source 的配置上限，并通过搭档评分约束交换点，因此配置不同时仍能保证自动交换点双门不透明。

## 6. 选中覆盖

`PortalPair` 提供以下公开 API：

```csharp
public CaptureDisplayGroup SelectedPortal { get; }
public void SelectPortal(CaptureDisplayGroup portal);
public void ClearSelectedPortal();
```

规则：

- `SelectPortal(A)`：A 固定为 source，B 接收透明。
- `SelectPortal(B)`：B 固定为 source，A 接收透明。
- 选中期间跳过自动 source 竞争，但仍每帧重算评分和 alpha。
- 选中模式沿用同一自适应阈值公式。
- 传入非本对门时抛出 `ArgumentException`，传入空引用时抛出 `ArgumentNullException`。
- `ClearSelectedPortal()` 立即恢复自动仲裁。
- 手动选中、清除选中造成的目标变化立即应用，不做时间插值或交叉淡化。

## 7. 重算与应用时机

普通模式每帧在 `LateUpdate` 评估。以下事件强制立即评估：

1. `Start` 和 `OnEnable` 初始化。
2. 玩家引用切换。
3. `SelectPortal` 和 `ClearSelectedPortal`。
4. `Teleport` 完成玩家位置、角度、速度、相机和同向镜像处理后。

传送末尾的强制评估不使用上一帧 source，也不等待下一次 `LateUpdate`。因此出口门在传送调用结束时已经恢复不透明，其搭档立即使用玩家出口位置重新计算 alpha。

缺少玩家或任一门时，双门恢复不透明；`OnDisable` 同样恢复双门 alpha 为 1，并清除自动 source 缓存。

## 8. 颜色合成

`CaptureDisplayGroup.SetViewAlpha` 接收并钳制 alpha，然后立即调用 `UpdateViewColor`：

- alpha 完全由 `PortalPair` 下发，本门不再查找搭档并自行计算透明目标。
- 原有 RGB 冷暖仍根据玩家到本门视觉中心本地 Y 轴的距离计算。
- 玩家引用为空时仍允许恢复或应用 alpha。
- 开门进度 `_openProgress` 只影响 RGB 明暗，不影响 alpha。
- `ViewAnchor` 对 Pair 公开，优先使用 `viewCenter`，否则回退到输出父节点或组根节点。

## 9. 自动化验证

`PortalTeleportTests` 已覆盖：

- 正面接近时仅搭档透明，离开范围后双门恢复不透明。
- 双门同时进入衰减范围，且 A/B 使用不同最大阈值时，等分点双门 alpha 都为 1。
- 越过等分点后透明目标正确交换，并从 1 进入新的衰减曲线。
- 选中覆盖自动结果、选中后距离衰减、清除选中及拒绝跨门对选择。
- 背面惩罚使正面门优先，运行时换向后透明目标按新朝向交换。
- 真实 B → A 物理传送结束时，出口 A 当帧恢复不透明。

## 10. 编辑器人工验收

可在更新后的 `TeatScene` 中继续检查：

- 正面接近、背面绕门和沿门面横向移动。
- 双门同时进入范围并反复穿越自动交换中线。
- 旋转门及运行时切换四种朝向组合。
- 选中 A/B、清除选中和多对门并存。
- A → B 与 B → A 传送瞬间的出口透明状态。
